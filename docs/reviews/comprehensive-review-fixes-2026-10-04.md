# 包括的レビュー指摘への対応

対象: RadiCorder。基点: main `b7782c8`（PR #43のマージ後）。作成日: 2026-10-04（日本時間）。

## 対応範囲

レビューのC01〜C15を対象に、正常系のAPI契約、録音形式、DBスキーマを保ったまま異常系を修正した。C14は更新可能な依存を修正したが、Tailwind 3の開発用依存には未解決のアドバイザリが残る。問題ごとに日本語タイトルのコミットへ分けた。

| 指摘 | 修正内容 | 確認した結果 |
|---|---|---|
| C01 HTML処理の入れ子によるXSS | DOMPurifyで全体を処理し、従来の許可タグ・リンクの条件を適用 | 不正なイベント属性、JavaScript URL、SVG等を除去。安全な書式とリンクは保持 |
| C02 録音削除失敗後の追跡状態 | 削除で変更したEF追跡状態を復元。読み取り時のHLS補正保存を避ける | 同じDbContextで次の録音を削除しても、失敗した録音のDB情報とファイルを保持 |
| C03 FFmpegログの未処理例外 | stdout/stderrをawaitする処理へ変更。ログI/O障害を記録して読み取りを継続 | 保存先が使用できなくてもFFmpegの終了結果を返し、アプリ全体を停止させない |
| C04 予約の再有効化 | 起動時の準備と明示的な再有効化を分離。実行終了待ちとDB状態の比較更新を導入 | 中断した予約をPendingへ戻せる。実行中の停止・終了保存と競合しない。確定済みや復旧待ちは再投入しない |
| C05 配信先への認証トークン送信 | 配信専用HttpClientで自動リダイレクトを止め、各接続先を検証 | マスターからのURLとリダイレクト先が許可条件を満たさなければ、トークン送信前に拒否 |
| C06 CSVフォームのミドルウェア不足 | UseAntiforgeryを既存の検証トークン付きUIに接続 | 正しいトークンでフォーム処理へ到達。不足時は400。ミドルウェア不足の500を解消 |
| C07 音声指紋解析の停止 | キャンセル・タイムアウト時にプロセスツリーを終了し出力処理を回収。呼び出し元のキャンセルを伝播 | キャンセルを空配列としてキャッシュせず、子プロセスを残さない |
| C08 更新後処理の失敗隠蔽 | 古い番組・予約の削除とキーワード予約の失敗を更新結果へ反映。ルール単位でDBスコープを分離 | 他の取得対象の成功は保存し、全体失敗時は最終成功日時を進めない。DB検索障害を空結果に変換しない |
| C09 不完全ならじる設定XML | 必須の日次番組表URLと広告されたHLS URLを保存前に検証 | 不正な日次URLでは既存定義と確認日を保持。現在使っていない任意のnoa/detail URLは、欠落時に既存値を保持 |
| C10 FFmpeg引数の文字列連結 | 本体の呼び出しをArgumentListへ移行。HTTPヘッダーの改行を拒否しconcatリストの引用符をエスケープ | URLや保存先の引用符から引数が増えない。従来のIFfmpegService実装にはエスケープ済み文字列で連携 |
| C11 別の破損した復旧情報 | 復旧情報を個別に扱い、DB確定と復旧記録の掃除を分離 | 他の不正なJSONを保持しながら対象ジョブの掃除を完了。DB確定後の掃除失敗で録音を失敗へ戻さない |
| C12 手動類似抽出のTask.Run | 要求キューとBackgroundServiceへ移行 | 実行スコープ・ホスト停止・キャンセルを管理。待機要求の無制限な増加を防ぐ |
| C13 応答本文の期限とサイズ | 定義・番組表・プレイリスト・画像を制限付きで読み取り。音声中継にも期限を適用 | ヘッダー取得後の停止やContent-Length不明の過大本文を検出。XMLの外部実体を禁止 |
| C14 npm依存 | 未使用ts-nodeを削除。wsなど修正可能な依存を更新 | 実行時監査は検出0件。開発用の残件は下記 |
| C15 予約削除の成功誤報 | DB障害を失敗として返し、単件削除を追跡状態に残さない実装へ変更 | 削除トリガーによるDB障害で予約を保持。続けて別の予約を削除しても失敗分を削除しない |

追加で、MVC向けに登録されていた例外フィルターをMinimal APIのエンドポイントフィルターへ置き換えた。本番では未処理例外の内部情報を応答へ出さず、ドメイン例外は400のJSONで返す。

未使用のスケジューラ用私有メソッド、テストのリフレクション専用ラッパー、TypeScriptと重複したScripts直下の古いJavaScriptを削除した。ライセンス一覧も現在の依存に合わせた。

## 維持する契約

- DBエンティティ、スナップショット、マイグレーション、enumの数値に変更なし。追加マイグレーション不要。
- 正常系の公開APIのpath・schema・入力・応答を既存のOpenAPI fixtureで確認。
- 番組情報、タグ、録音の保存パス、録音形式、SignalRのDTOを維持。
- 従来のIFfmpegServiceの文字列版は維持。本体実装は構造化引数を使う。
- 起動時には非Pendingの予約を初期化せず、利用者が再有効化する場合だけ状態を明示的に戻す。
- 破損した復旧情報は自動削除しない。安全に再録音の可否を判断できない再有効化は拒否する。
- WebやWorkerを使わず直接業務処理を実行する構成も維持。手動類似抽出の要求キューを使う場合はBackgroundServiceの登録が必要。

異常系では従来と結果が変わる。たとえばDB障害は成功や空結果として返さず、取得先が不正な配信URLは拒否する。安全性の修正に必要な変更である。

- Releaseビルド成功、ロジック445件・Web22件の全467件が成功（失敗・スキップ0件）。DB読み戻し、マイグレーション互換性、バックアップのintegrity_check、API契約を含む。

- 外部サービスを使わず、実際のFFmpegで引用符・空白を含むディレクトリでの結合を確認。ffprobeでAAC、TagLibでタイトル・説明・出演者を確認した。

## Canaryへの影響

実サービスを呼ぶCanaryの業務処理の構成は維持する。配信処理では新しい `HttpClientNames.RadikoStreaming` を使うため、テスト用HTTPハンドラーを旧 `HttpClientNames.Radiko` にだけ登録しているテストは差し替え先の追随が必要。

Canary mainのコードを本体へ参照させた別コピーではコンパイルが通り、無変更のfixtureは56/61件成功した。失敗した5件はいずれも配信テストの差し替え先によるもの。`ProxyTests.cs`の登録先1箇所を `HttpClientNames.RadikoStreaming` へ変更すると61/61件成功した。Canaryリポジトリ自体はこのPRで変更していない。本体を更新する際に、このfixture設定も更新する。

## 残る開発用依存の問題

`npm audit --omit=dev` は検出0件。全依存の監査では、開発用 `braces` 3.0.3を原因とするhighの5パッケージが残る。原因のアドバイザリは [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) の1件。

深い入れ子のglobパターンによるビルド処理のDoSが対象。確認時点でnpmレジストリの最新版は3.0.3で、修正版が未提供。現在のビルド設定はリポジトリ内の固定パターンを使い、実サービスの番組データやWebリクエストをglobパターンに渡さない。サーバー・ブラウザへbracesを配布しない。

通常の表示を維持するため、Tailwind 4への移行は別作業とする。修正版公開後にlockfileを更新するか、画面差分を確認しながらTailwind 4へ移行する。監査0件になったと扱わない。
